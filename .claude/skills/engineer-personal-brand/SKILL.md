# Personal branding for a software engineer

Use this skill whenever you write copy, structure pages, or pick what to feature on the
portfolio or on Job's public profiles. Always also apply `portfolio-privacy-guard`.

## Positioning
- Lead with **level + domain + proof**: "Senior mobile engineer · 10+ years · apps used by
  millions in fintech, media and logistics." Avoid adjectives that can't be proven
  ("passionate", "rockstar", "perfectionist").
- One clear niche statement, then breadth. Job's niche: *native-feeling, high-performance
  mobile apps (Android, React Native, Flutter) that scale and work offline.*
- Every claim gets evidence: a number, a public link, an award, or a code sample.

## The 10-second recruiter test
Above the fold a recruiter must find: name, title, seniority, core stack, 2–3 proof points,
availability (role type, remote/time zone), and a way to contact. Check it on a 375px screen.

## Case-study formula (problem → approach → outcome)
1. **Context** (one sentence): company, product, users, your role, team size, timeline.
2. **Problem**: the constraint or pain in business terms (slow cold start hurt ratings).
3. **Approach**: 3–5 bullets of what *you* decided and built; name trade-offs and tools.
4. **Outcome**: metrics with baseline ("cold start −40%, rating to 4.9★"), plus a quote if
   you have permission.
5. **Artefacts**: public store screenshots, architecture diagram (sanitised), code snippet.
Keep each under ~350 words on the page; link to a longer write-up if needed.

## Writing rules
- Active voice, first person, past tense for results, present for capabilities.
- Numbers as digits, units explicit (40%, 1M+, 3 months). Mark unverified numbers
  `TODO(verify)` — never invent metrics.
- Headlines: short, one italic emphasis word (house style): "Apps that *feel* native."
- Bullets start with a verb: Built, Led, Cut, Shipped, Migrated, Mentored.
- Tech chips: max 6 per project, most important first.
- Respect NDAs: describe security-sensitive work (identity, locks, payments) at the
  outcome level only.

## Services framing
For each service: who it's for, the outcome, what's included, typical timeline, CTA.
Services for Job: Mobile app builds (MVP→scale), Architecture & migrations (RN New
Architecture, KMM, Compose), Performance & reliability audits, Team leadership & mentoring.

## Social proof hierarchy
Awards (MTN App of the Year 2021, IEEEmadC 2018) → install counts from public stores →
company logos (with permission) → open source stars → community leadership → certifications.

## Profile consistency
Same headshot, title, one-liner and links across LinkedIn, GitHub README, X, Play developer
page and the site. GitHub profile README should mirror the site hero and link back.
Pin repos that show current skills (Compose, RN/Expo, Flutter, KMM), not 2016 coursework.
